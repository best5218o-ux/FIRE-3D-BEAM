# FIRE-3D BEAM 내부 PC 시범운용 절차서

소방활동 정보카드 → 3D 지휘화면·사전 활동계획·IFC 변환프로그램(FIRE-3D BEAM)을 내부 PC(행정망, 인터넷 없음)에서 시험하는 절차입니다.
설치 세부는 같은 폴더의 `설치안내.md` 를 따릅니다. 이 문서에는 개인 이름·연락처를 적지 않습니다(역할만 적음).

---

## 1. 목적

1. 인터넷이 없는 일반 사무용 PC 에서 **관리자 권한 없이** 설치·실행되는지 확인한다.
2. **실제 정보카드 1~3건**으로 변환해, 지휘관 관점에서 결과(진입로·대피로·소방시설 위치/확실성·층 전환·IFC)가 쓸 만한지 평가한다.
3. 검수(교정) 루프가 현장 담당자 손으로 돌아가는지, 걸리는 시간이 얼마인지 확인한다.
4. 개인정보(관계인 성명·연락처) 제외와 **결과물 반출 금지** 원칙이 절차로 지켜지는지 확인한다.

성공 기준(잠정): 설치·자체시험 통과, 카드 3건 모두 변환 완료, 평가표 '정확' 비율과 '누락' 항목 목록 확보, 반출 0건.

## 2. 역할

| 역할 | 하는 일 |
|---|---|
| 시범 책임자 | 일정·대상 카드 선정, 결과 판정, 회수·삭제 확인 서명 |
| 전산(보안) 담당 | 반입 매체 보안검사, SHA256 확인, 백신 예외 필요 시 처리 |
| 평가자(지휘관·진압대원) | 3D 지휘화면·활동계획 확인, 평가표 작성 |
| 검수자 | 검수화면에서 자동 인식 교정, 소요 시간 기록 |

## 3. 준비물

### 3-1. PC 사양
| 항목 | 최소 | 권장 |
|---|---|---|
| 운영체제 | Windows 10 64비트 | Windows 10/11 64비트 최신 업데이트 |
| CPU | 2코어 | 4코어 이상 |
| 메모리 | 4GB(이때는 `--rules` 규칙만 권장 — AI 교차검증은 도면당 약 2GB) | 8GB 이상 |
| 디스크 여유 | 1.5GB | 3GB(결과·학습데이터 누적) |
| 그래픽 | 불필요(GPU 안 씀) | 3D 화면이 부드러우려면 내장 그래픽 가속 켜짐 |
| 브라우저 | 크롬 또는 엣지 | 최신판 |
| 권한 | 일반 사용자 | — |

### 3-2. 반입물
| 파일 | 내용 |
|---|---|
| `FIRE-3D-BEAM_offline.zip` | 설치판 전체(Python·라이브러리·Tesseract·AI 모델·가상 시험 자료 포함, 약 260MB) |
| `FIRE-3D-BEAM_offline.zip.sha256` | zip 의 SHA256 값(한 줄) |

설치판에는 실제 정보카드나 개인정보가 없습니다(시험 자료는 모두 가상 건물).

### 3-3. 반입 절차 (USB 또는 내부망 자료전송)
1. 인터넷 PC 에서 SHA256 값을 따로 기록해 둔다(종이 또는 결재 문서): `FIRE-3D-BEAM_offline.zip.sha256` 내용.
2. 기관 반입 절차에 따라 **보안 USB 또는 망간 자료전송 시스템**으로 옮기고, 전산(보안) 담당이 **악성코드 검사**를 한다.
3. 내부 PC 에서 무결성 확인(PowerShell):
   ```
   Get-FileHash C:\반입\FIRE-3D-BEAM_offline.zip -Algorithm SHA256
   ```
   출력된 값이 기록해 둔 값과 **한 글자도 다르지 않아야** 한다. 다르면 설치하지 않고 다시 반입.
4. 푼 뒤 파일별 확인이 필요하면 `SHA256SUMS.txt`(폴더 안 모든 파일의 값) 를 쓴다(예: 특정 파일을 백신이 격리했는지 확인).
5. 반입 기록: 날짜, 매체, SHA256 앞 12자리, 확인자(역할)를 반입 대장에 적는다.

## 5. 첫 실행 자체시험

`자체시험.bat` 을 더블클릭(설치 때 한 번 자동 실행됨 — 시범 당일 PC 를 켠 뒤 한 번 더 실행).
가상 표준양식 정보카드(가상 건물, 진압작전도 포함)로 다음 10개 항목을 자동 확인한다.

| # | 항목 | 통과 기준 |
|---|---|---|
| 1 | 결과 파일 5종 | 3D 지휘화면·IFC·활동계획·검수화면·결과 JSON 생성 |
| 2 | 표준양식 해석 | `양식=std` · 층별현황 행 수 표시 |
| 3 | 진압작전도 인식 → 외부 부서 | 부지 출처 = 진압작전도, 면·사다리차 후보 수 표시 |
| 4 | 소방시설 레이어 | 항목 수 > 0 |
| 5 | 대피로·진입로 | 진입구·층 수 표시, 오류 없음 |
| 6 | AI 모델 교차검증 | 도면마다 성공(실패 시 규칙 결과로 계속 — 원인 기록) |
| 7 | 개인정보 제외 | 관계인 성명·연락처가 결과에 없음 |
| 8 | 오프라인 | 결과 화면에 외부 스크립트·글꼴·CDN 없음 |
| 9 | IFC4 열기 | 층·벽·문·계단·공간 개수 표시 |
| 10 | 검수 반영(사람 대신 자동 판정 파일로 `검수.bat` 과 같은 경로) | 3D·IFC·활동계획 재생성 + 학습 라벨 생성 |

추가 확인(사람): `C:\FIRE-3D BEAM\결과\_자체시험\` 의 `*_3D지휘화면.html` 을 열어 3D 가 돌아가는지(마우스 끌기·휠), 층 버튼이 바뀌는지 본다.
자체시험 소요 시간을 기록한다(평가표 D-1).

## 6. 실제 정보카드로 시범 (1~3건)

### 6-1. 원칙
- **원본 정보카드는 내부 PC 에서만** 다룬다. 결과물(HTML·IFC·JSON·PDF 합본·검수 파일·학습데이터·화면 캡처)은 **반출 금지**.
- 평가 결과는 **아래 평가표(글자)만** 작성해 보고한다. 평가표에 주소·상호·관계인 등 카드 내용을 적지 않는다(건물은 `시범1·2·3` 으로 부름).
- 관계인 성명·연락처는 기본 제외된다. 시범에서는 `FIRE3DBEAM_INCLUDE_CONTACTS` 를 켜지 않는다.

### 6-2. 대상 선정
| 순번 | 권장 유형 | 이유 |
|---|---|---|
| 시범1 | 표준양식 PDF, 3~5층, 평면도 포함 | 기본 경로 |
| 시범2 | 지하층·기준층(여러 층 한 도면)이 있는 건물 | 층 정합·수직동선 |
| 시범3 | 평면도가 카드 밖 별도 파일이거나 스캔 품질이 낮은 카드 | 별도 도면 붙이기·약점 확인 |

### 6-3. 진행
1. 작업 폴더 `C:\FIRE-3D BEAM\시범\시범1\` 을 만들고 카드 PDF 를 복사(원본 보관 위치에서 복사, 원본은 그대로).
   따로 받은 평면도가 있으면 같은 폴더에 층 이름으로(`지상1층.png`, `B1.pdf`, `진압작전도.jpg`).
2. 폴더째 `변환.bat` 위에 끌어다 놓는다. 창에 나오는 소요 시간·경고(`!`, `✗`)를 평가표에 옮겨 적는다.
   - `개인정보 검사: … 모두 결과에 없음` 확인(✗ 이면 즉시 중단, 결과 삭제, 책임자 보고).
3. 자동으로 열린 `*_3D지휘화면.html` 과 `*_활동계획.html` 로 **7절 체크리스트**를 평가한다.
4. `*_검수화면.html` 로 검수(8절) → `검수.bat` → `*_검수반영.html` 로 다시 평가(평가표 '검수 후' 열).
5. 카드 1건당 목표 시간: 변환 5분 이내, 평가 20분, 검수 30분(실측 기록).

## 7. 확인 체크리스트 (지휘관 관점)

3D 지휘화면(`*_3D지휘화면.html`)과 사전 활동계획(`*_활동계획.html`)을 **정보카드 원본·현장 지식과 비교**한다.

| 구분 | 확인할 것 | 어디서 |
|---|---|---|
| 진입로 | 주출입구·진입구 위치가 실제와 맞는가, 진입구→계단 경로가 실제 통행 가능한가 | 3D '진입로', 활동계획 3절 |
| 대피로 | 실별 대피 경로가 벽을 뚫지 않는가, 기준 초과·한 방향 피난 표시가 타당한가 | 3D '대피로', 활동계획 5절·6절 |
| 수직동선 | 계단·승강기 개수·위치·연결층이 맞는가(특별피난계단·비상용승강기 포함) | 3D 계단/승강기, 활동계획 4절 |
| 소방시설 위치 | 옥내소화전·방수구·송수구·수신기·비상콘센트 위치가 도면과 맞는가 | 3D '소방시설 분류·확실성' |
| 확실성 표시 | 속 찬 기둥=위치 확인, 와이어+점선 5 m 원=추정, 층 배지=수량만 — 표시가 구분되어 오해 없이 읽히는가 | 3D 소방시설, 활동계획 5절 범례 |
| 수량 | 정보카드 층별 소방시설 수량과 화면 표가 같은가, 불일치 경고가 맞는가 | 3D 오른쪽 층별 표, 확인사항 |
| 층 전환 | 층 버튼으로 층을 바꿀 때 층·도면·기호가 맞게 바뀌는가, 층 사이 위치가 어긋나지 않는가 | 3D 층 버튼 |
| 외부 부서 | 면별 소방차 접근, 펌프차→송수구 거리·호스 본수, 소화전, 고가사다리차·진입창 후보가 현장과 맞는가 | 활동계획 2절, 3D 부지 |
| 위험요소 | 정보카드 ⑨ 위험물·가스가 맨 위에 빠짐없이 나오는가 | 활동계획 1절, 확인사항 |
| 확인사항 | 경고(카드↔도면·교차검증·대피로) 중 실제 문제인 것과 헛경고 비율 | 활동계획 6절 |
| 화점 지정 | 한 층에 화점을 찍었을 때 경로·호스 본수·공기호흡기 귀환·인명검색 순서가 상식에 맞는가 | 3D 화점 지정 |
| IFC | 기관 IFC 뷰어(있으면)로 `*.ifc` 가 열리고 층·벽·문·계단·소방시설이 보이는가 | IFC 뷰어 |
| 개인정보 | 관계인 칸에 역할과 '기재됨'만 보이고 성명·연락처가 없는가 | 3D 정보카드 절, 활동계획 꼬리말 |

## 8. 검수 루프 사용법

1. `*_검수화면.html` 을 연다 → 오른쪽 「검수 필요」 목록 위에서부터 처리(의심도 높은 순).
2. 벽·문 교차검증(규칙 ↔ AI 모델) 항목: 도면의 점선을 보고 `Y`(모델이 맞음) / `N`(규칙이 맞음) / `L`(나중에).
3. 기호: 맞음/틀림, 빠진 기호 `A`→`1~5`→클릭, 빠진 계단·승강기 `S`→상자 그리기, 문 `D`, 벽 `W`, 되돌리기 `Ctrl+Z`.
4. 층정합: `G` 로 아래층 벽을 겹쳐 보고 `O`(정상)/`X`(불량), 어긋나면 `Ctrl+화살표`.
5. 층을 다 보면 `Enter`(검수 완료 — 완료한 층만 학습데이터).
6. `Ctrl+S` → 다운로드 폴더의 `*_corrections.json` 을 `검수.bat` 위에 끌어다 놓기 →
   `*_검수반영.html`·`*_검수반영.ifc`·`*_검수반영_활동계획.html` 생성, `C:\FIRE-3D BEAM\학습데이터\` 누적, `채점현황.html` 갱신.
7. 다운로드 폴더의 `*_corrections.json` 은 결과 폴더로 복사되므로(`_검수기록.json`) 다운로드 폴더 쪽은 삭제한다.
8. 기록: 검수 항목 수, 처리 수, 걸린 시간, 모델이 맞은 비율(채점현황의 「검수 기반 성능」).

## 11. 회수·삭제 절차

시범 종료 후(또는 중단 시) 시범 책임자 입회하에:

2. 결과 삭제:
   - 시범 작업 폴더 `C:\FIRE-3D BEAM\시범\` 전체(카드 사본, `*_변환결과` 폴더, `*_입력합본.pdf` 포함)
   - `C:\FIRE-3D BEAM\결과\`, `C:\FIRE-3D BEAM\학습데이터\`, `C:\FIRE-3D BEAM\logs\`, `C:\FIRE-3D BEAM\채점현황.html`
   - 브라우저 `다운로드` 폴더의 `*_corrections.json`
   - 검수화면 자동 저장분: 크롬·엣지 **설정 → 개인정보 → 인터넷 사용 기록 삭제 → 쿠키 및 기타 사이트 데이터**(파일로 연 페이지의 자동 저장 포함 — 시범 기간만 선택)
   - 임시 폴더: `%TEMP%` 안 `fb_*`·`tmp*` 중 시범 기간 것, `C:\Users\Public\FIRE-3D-BEAM_tmp`(있으면)

4. 휴지통 비우기. 기관 규정이 완전삭제(덮어쓰기)를 요구하면 기관 승인 도구를 쓴다.
